# חיבור ל-Supabase — מה צריך לעשות

בלי ההגדרות האלה האפליקציה עובדת בדיוק כמו קודם: הכל נשמר במכשיר, בלי חשבון ובלי שיתוף.
אחרי ההגדרה נפתחים חשבונות, טיולים משותפים וסנכרון חי בין כל המשתתפים.

ההגדרה כולה לוקחת בערך **10 דקות** ורצה על התוכנית החינמית של Supabase.

---

## 1. יצירת פרויקט

1. להיכנס ל־[supabase.com](https://supabase.com) וליצור פרויקט חדש (Free).
2. לבחור אזור קרוב — `Frankfurt (eu-central-1)` נותן את ההשהיה הנמוכה ביותר מישראל.
3. לשמור את סיסמת מסד הנתונים במקום בטוח (לא נדרשת לאפליקציה, אבל קשה לשחזר).

## 2. הרצת הסכימה

**אין צורך ליצור אף טבלה ידנית.** הקובץ יוצר את הכל — 14 טבלאות, חוקי ההרשאות, הטריגרים
וה-bucket למסמכים — בהרצה אחת.

1. בפרויקט: **SQL Editor → New query**.
2. להעתיק את כל התוכן של [`migrations/0001_init.sql`](migrations/0001_init.sql) ולהדביק.
3. **Run** (או `Ctrl/Cmd + Enter`).

בסוף אמורה להופיע הודעת `Success`. הקובץ בטוח להרצה חוזרת — אם משהו נקטע באמצע, פשוט
מריצים אותו שוב מההתחלה.

> אם מופיעה שגיאה על `storage` — זה אומר שהרצת את הקובץ מחוץ ל-Supabase. בתוך Supabase
> הוא יעבור בלי הערות.

## 3. הגדרות התחברות

**Authentication → URL Configuration**:

| שדה | ערך |
| --- | --- |
| Site URL | `https://rozentravel-greece.vercel.app` |
| Redirect URLs | `https://rozentravel-greece.vercel.app/auth/callback`<br>`http://localhost:3000/auth/callback` |

**Authentication → Providers → Email**: לוודא ש-Email מופעל. אפשר להשאיר
״Confirm email״ דלוק — הכניסה היא בקישור קסם ממילא.

> **חשוב לדעת:** שרת המייל המובנה של Supabase מוגבל לכ-3 מיילים בשעה. זה מספיק כדי להתחיל,
> אבל אם המשפחה מתחברת ביום אחד — כדאי לחבר ספק SMTP משלך תחת
> **Project Settings → Authentication → SMTP Settings** (Resend ו-Brevo נותנים חינם מספיק).
> בלי זה חלק מההזמנות פשוט לא יגיעו, וזה נראה כאילו משהו שבור.

## 4. המפתחות

**Project Settings → API**, להעתיק:

- `Project URL`
- `anon` `public` key

שני אלה מיועדים לדפדפן ובטוחים לחשיפה — הם מוגבלים לגמרי על ידי חוקי ה-RLS שהרצנו.
**את מפתח ה-`service_role` אסור להכניס לאפליקציה.**

## 5. חיבור ל-Vercel

ב-Vercel: **Settings → Environment Variables**, להוסיף לשלוש הסביבות
(Production, Preview, Development):

```
NEXT_PUBLIC_SUPABASE_URL       = https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY  = <anon public key>
```

ואז **Deployments → Redeploy**. המשתנים נצרבים בזמן הבילד, ולכן חובה לפרוס מחדש.

לפיתוח מקומי: להעתיק את `.env.example` ל-`.env.local` ולמלא את אותם שני ערכים.

---

## אם משהו לא עובד

באפליקציה יש מסך **בדיקת חיבור** בכתובת `/setup` (יש אליו קישור גם מההגדרות).
הוא בודק חמישה דברים מול הפרויקט שלך ואומר בדיוק מה חסר:

| בדיקה | מה זה אומר אם נכשל |
| --- | --- |
| משתני הסביבה | לא הוגדרו ב-Vercel, או שלא נעשה Redeploy אחרי ההגדרה |
| חיבור לפרויקט | הכתובת שגויה, המפתח שגוי, או שהפרויקט ישן (חינמי נכנס לשינה) |
| הסכימה הורצה | לא הרצת את `0001_init.sql` ב-SQL Editor |
| הטבלאות קיימות | הסכימה רצה חלקית |
| אחסון מסמכים | ה-bucket לא נוצר |

הבדיקה רצה מהדפדפן עם אותו מפתח שהאפליקציה משתמשת בו, כך שהיא בודקת בדיוק את מה
שהאפליקציה רואה.

---

## 6. השימוש הראשון

1. לפתוח את האפליקציה → **״התחברות״** במסך ״הטיולים שלי״.
2. להזין אימייל → מגיע קישור → לוחצים → נכנסים.
3. במסך ״הטיולים שלי״ יופיע באנר: **״יש טיול אחד שנשמר במכשיר הזה ועדיין לא בחשבון״** →
   **״העלאה לחשבון״**. זה מעלה את טיול יוון הקיים לענן.
4. להיכנס לטיול → **עוד → הגדרות → ״מי בטיול הזה״**.
5. **״קישור לשיתוף״** יוצר קישור שאפשר לשלוח בוואטסאפ. כל מי שפותח אותו ומתחבר מצטרף לטיול.
   לחלופין **״הזמנה למייל״** — הכתובת מצורפת אוטומטית ברגע שהיא נכנסת בפעם הראשונה.

## הרשאות

| תפקיד | יכול |
| --- | --- |
| **בעלים** | הכל, כולל הזמנת אנשים, שינוי הרשאות ומחיקת הטיול |
| **עריכה** | לקרוא ולשנות הכל בטיול — מסלול, מלונות, הוצאות, מסמכים |
| **צפייה** | לראות הכל, בלי לשנות דבר |

כל אחד יכול לעזוב טיול בעצמו. רק בעלים יכולים להסיר מישהו אחר.

> **״מטיילים״ ו״חברי טיול״ הם שני דברים שונים בכוונה.** מטייל הוא מי שההוצאות מתחלקות בינינו —
> יכול להיות ילד בלי טלפון. חבר טיול הוא מי שיש לו גישה לאפליקציה. אפשר להיות אחד בלי השני.

## מסמכים

קבצים עולים ל-bucket פרטי בשם `trip-documents`, בנתיב `<trip_id>/<file>`. הגישה נשלטת
באותם חוקים כמו הטיול עצמו, והקישורים שהאפליקציה מייצרת תקפים ל-10 דקות בלבד.

קבצים שהועלו **לפני** ההתחברות נשארים במכשיר בלבד — צריך להעלות אותם מחדש כדי שהמשפחה
תראה אותם. האפליקציה אומרת את זה כשמנסים לפתוח קובץ כזה ממכשיר אחר.

## סנכרון וקונפליקטים

- כל שינוי נשמר קודם במכשיר ואז נשלח לשרת, כך שהאפליקציה עובדת גם בלי רשת.
- כשאין חיבור מופיעה הודעה, והשינויים נשלחים ברגע שהחיבור חוזר.
- שינויים של אחרים מגיעים בזמן אמת, וגם כשחוזרים לאפליקציה או כשהרשת חוזרת.
- **פתרון קונפליקטים הוא ״האחרון מנצח״ ברמת השורה.** אם שני אנשים עורכים את *אותה* פעילות
  בו־זמנית, השמירה המאוחרת גוברת. עריכות של דברים שונים לא מתנגשות.

> **בעמוד Database → Tables יופיע `Realtime: Disabled` ליד `profiles` ו-`trip_invites`. זה מכוון.**
> 12 הטבלאות של תוכן הטיול משודרות בזמן אמת; שתי אלה לא, כי אין מה לשדר — שם ותמונה כמעט
> ולא משתנים, והזמנות נקראות כשפותחים את מסך המשתתפים. הטבלאות עצמן עובדות רגיל לגמרי.

## בדיקת חוקי ההרשאות

חוקי ה-RLS נבדקים מול Postgres אמיתי:

```bash
createdb mtp_test
psql -d mtp_test -f supabase/tests/00_local_auth_shim.sql
psql -d mtp_test -f supabase/migrations/0001_init.sql
psql -d mtp_test -c "create schema tst; create table tst.ids(k text primary key, id uuid);
  grant usage on schema tst to authenticated; grant select,insert on tst.ids to authenticated;"
psql -d mtp_test -f supabase/tests/10_rls_tests.sql
```

33 בדיקות: מי רואה מה, מי יכול לערוך, שאדם זר לא רואה כלום, שקישור הזמנה עובד, שמחיקת טיול
מנקה את כל מה שתלוי בו.

# My Trip Planner

אפליקציית Web לניהול ותכנון טיולים בחו״ל — מסלול יומי, מפה, מלונות, טיסות, רכב, מסמכים ותקציב,
הכל במקום אחד. בנויה Mobile First, עובדת מצוין בטלפון, בטאבלט ובדסקטופ, ונשמרת מקומית כך שהיא
זמינה גם בלי רשת בזמן הטיול.

```bash
npm install
npm run dev            # http://localhost:3000
npm run build          # בילד רגיל של Next
npm start              # הרצת הבילד
npm run typecheck
npm run lint
```

### פריסה

`npm run build` הוא בילד Next.js רגיל — זה מה ש-Vercel מריצה ללא שום הגדרה נוספת. אין בפרויקט
קוד צד־שרת, כך שכל 19 המסלולים מתרנדרים מראש ל-HTML סטטי גם בבילד הזה.

לאירוח על שרת קבצים פשוט (GitHub Pages, S3, Netlify Drop) יש מצב ייצוא סטטי:

```bash
npm run build:static   # יוצר תיקיית out/ עצמאית לחלוטין
npm run serve:static
```

### שני מצבי הפעלה

| | **מקומי** (ברירת מחדל) | **ענן** |
| --- | --- | --- |
| מתי | בלי משתני סביבה של Supabase | אחרי [הגדרת Supabase](supabase/README.md) והתחברות |
| נתונים | בדפדפן של המכשיר בלבד | Postgres, מסונכרן, עם עותק מקומי לעבודה בלי רשת |
| שיתוף | ייצוא/ייבוא קובץ גיבוי | הזמנת אנשים לטיול עם הרשאות צפייה או עריכה |

המעבר בין המצבים הוא התחברות והתנתקות — הקוד זהה, רק ה-`TripRepository` מתחלף.

בכניסה הראשונה האפליקציה ריקה: מסך ״הטיולים שלי״ מציע ליצור טיול, ואשף היצירה בונה את
הימים, המטיילים והשלד של הטיסות והמלון לפי התאריכים שהוזנו.

## הטכנולוגיה

- **Next.js 16** (App Router) + **React 19** + **TypeScript** — הכל רץ בצד הלקוח, כך שהבילד
  הרגיל מתרנדר מראש לגמרי, ו-`build:static` מייצר חבילה סטטית שאפשר לארח בכל מקום.
- **Tailwind CSS v4** — Design tokens ב-CSS, מצב בהיר וכהה, RTL מלא באמצעות logical properties.
- **Zustand** — ניהול מצב עם undo, ושמירה אוטומטית (debounced) דרך שכבת ה-repository.
- **dnd-kit** — Drag & Drop במסלול ובמסך המקומות, כולל תמיכה במגע ובמקלדת.
- **Leaflet / react-leaflet** — מפה אינטראקטיבית ללא צורך במפתח API.
- **Recharts** — גרפי התקציב.
- **idb** — קבצי מסמכים ב-IndexedDB.

### שכבות אבסטרקציה ל-API חיצוני

האפליקציה עובדת במלואה בלי אף שירות חיצוני. כל נקודה שבה *אפשר* לחבר API אמיתי עטופה
בממשק, כך שההחלפה היא מימוש אחד ולא שינוי במסכים:

| שירות | ברירת מחדל (ללא רשת) | חלופה מקוונת | הממשק |
| --- | --- | --- | --- |
| התמדה | `LocalStorageRepository` | `SupabaseRepository` | `TripRepository` (`lib/db/repository.ts`) |
| זמני נסיעה | הערכה מקומית לפי מרחק וסוג דרך | OSRM | `RoutingProvider` (`lib/services/routing.ts`) |
| שערי מטבע | טבלת שערים ידנית | frankfurter.dev (ECB) | `RatesProvider` (`lib/services/currency.ts`) |
| חיפוש מקומות וגיאוקודינג | — | OpenStreetMap Nominatim | `SearchProvider` (`lib/services/places-search.ts`) |
| עוזר AI | מנוע דטרמיניסטי מעל נתוני הטיול | מודל שפה | `AssistantProvider` (`lib/services/assistant.ts`) |

הניתוב המקוון כבוי כברירת מחדל וניתן להדליק אותו בהגדרות. חיפוש המקומות דולק כברירת
מחדל, כי הוא המקור היחיד לתוצאות.

### ה-backend

מימוש ה-Supabase נמצא ב-`src/lib/db/supabase-repository.ts`, וההגדרה המלאה — סכימה, חוקי
הרשאות, הזמנות ואחסון מסמכים — ב-[`supabase/README.md`](supabase/README.md).

שתי החלטות מרכזיות שם:

- **הסנכרון כותב שורות, לא מסמכים.** ה-store ממשיך למסור מסמך שלם בכל שינוי, וה-repository
  משווה אותו לתמונת המצב האחרונה ששודרה בהצלחה ושולח רק את ההפרש. סימון פריט בצ׳קליסט
  שולח `UPDATE` אחד.
- **כישלון רשת אינו מאבד כלום.** תמונת המצב המסונכרנת מתקדמת רק אחרי כתיבה מוצלחת, ולכן
  השמירה הבאה משדרת מחדש את כל מה שהצטבר בינתיים.

חוקי ההרשאות נבדקים מול Postgres אמיתי — 33 בדיקות ב-`supabase/tests/`.

## נתונים ופרטיות

כל הנתונים נשמרים בדפדפן של המכשיר בלבד:

- נתוני הטיול — `localStorage` תחת המפתח `mtp:data:v1`.
- קבצי מסמכים — IndexedDB (`mtp-files`), כדי לא לפוצץ את מכסת ה-localStorage.
- העדפות תצוגה — `mtp:settings:v1`.

שום מידע לא נשלח לשרת. בהגדרות יש **ייצוא גיבוי** ו**ייבוא גיבוי** בפורמט JSON — זו גם הדרך
להעביר טיול בין מכשירים, ולשתף אותו עם מישהו אחר עד שיחובר שרת.

## הערות מוצר

- **Undo** — כל פעולה הרסנית מציגה Toast עם ״בטל״, ובנוסף יש כפתור Undo קבוע בכותרת.
- **מחיקה** — תמיד עם דיאלוג אישור שמסביר מה בדיוק יימחק.
- **Empty states** — לכל מסך יש מצב ריק עם הסבר וכפתור פעולה.
- **אזהרות זמן** — כשזמן הנסיעה המשוער ארוך מהפער בין שתי פעילויות, המסלול מסמן את המעבר
  ומציין בכמה דקות חסרות.
- **מטבעות** — כל סכום נשמר במטבע המקורי שלו ומוצג לצידו הערך במטבע הטיול.
- **נגישות** — ניווט מקלדת, `aria-*` על כל הפקדים, מלכודת פוקוס בחלונות, כיבוד
  `prefers-reduced-motion`.
- **שיתוף** — הזמנה במייל או בקישור לוואטסאפ, שלוש רמות הרשאה, ואפשרות לעזוב טיול.
  ״מטיילים״ (מי שמתחלקים בהוצאות) ו״חברי טיול״ (מי שיש לו גישה) הם שני דברים נפרדים.
